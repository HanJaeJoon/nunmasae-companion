# 기여 안내

[English](CONTRIBUTING.md) | [한국어](CONTRIBUTING-KR.md)

틀린 정보를 알려 주거나 직접 고쳐 주는 기여를 환영한다. 고치기 어렵다면 [이슈](https://github.com/HanJaeJoon/nunmasae-companion/issues/new/choose)만 열어도 된다.

**스포일러 주의**: 이슈, PR의 제목과 본문에 아직 안 읽은 사람에게 스포일러가 될 내용을 쓸 때는 첫 줄에 `[스포일러 N권]`을 적는다.

## 데이터 고치는 법

이 앱의 유일한 가치는 스포일러 차단이다. 사실 하나의 권 번호가 틀리면 그 권을 읽는 사람에게 반전이 샌다.

1. **두 파일을 함께 고친다.** 한국어 문장과 권 번호의 원본은 `docs/data-draft.md`이고, 앱이 읽는 것은 `src/data/entries.json`이다. 한국어 문장(`ko`), 권 번호(`at`), `[주요]`(`major`)를 바꾸거나 사실을 더할 때는 두 파일을 함께 고친다. 영문 문장(`en`)이나 영문 이름(`name.en`)만 고칠 때는 `entries.json`만 고친다(이름은 `docs/glossary.json`도).
   - 초안의 줄 형식: `- 사실: 문장. (권: N) [주요] [출처: ...]`
   - JSON의 사실 형식: `{ "at": N, "ko": "...", "en": "...", "major": true }`
2. **권 번호(`at`)에는 근거를 적는다.** PR 본문에 권/장/쪽과 출처(책, 오디오북, 연재 회차 등)를 적는다. 권 번호를 모르는 사실은 넣지 않고, 확실하지 않으면 늦은 권으로 잡는다.
3. **문장은 직접 쓴 짧은 요약만.** 원문 인용, 명대사, 나무위키 문장 복사는 받지 않는다. 사실만 참고해서 새로 쓴다.
4. **원작 1~4권 내용만.** 후속작(피를 마시는 새 등) 내용은 넣지 않는다.
5. **주요 반전(`major`)**: 주요 반전에 해당하는 사실에는 초안에 ` [주요]`, JSON에 `"major": true`를 붙인다 (`true` 외의 값은 쓰지 않는다). 같은 반전을 말하거나 내비치는 사실은 모든 항목에서 함께 붙인다. 지금 읽는 권의 주요 사실은 상세 화면에서 눌러야 보인다. 붙일지 애매하면 PR 본문에 적어 주면 관리자가 정한다.
6. **영문 고유명사**는 `docs/glossary.json`의 표기를 따른다. 영문판 공식 표기를 확인했다면 용어집과 `entries.json`을 함께 고치고 출처를 적는다.
7. 이름이나 정체 자체가 뒤 권의 반전이면 이름이 처음 보이는 순간 새므로, 그 이름을 쓰는 항목을 따로 만들고 그 권의 `at`을 준다.

상세 규칙은 [`CLAUDE.md`](../CLAUDE.md)의 "절대 올리지 않는 것"과 "데이터 규칙"에 있다.

## 새 항목 추가

`docs/data-draft.md`의 알맞은 `##` 묶음(`종족`, `신`, `인물`(생물 포함), `장소`, `용어`) 아래에 절을 더한다.

```
### 이름
- type: character / race: 인간 / 소속: ...
- 사실: 문장. (권: 1) [출처: ...]
```

- `###` 제목은 항목의 `name.ko`와 같아야 한다. 인물, 생물이 아닌 항목은 `- type: place` (또는 `race`, `god`, `term`)만 적는다.
- `(권: N)`은 확정, `(권: N?)`은 추정이며 앱에는 N권으로 들어간다. `(권: )` 빈칸은 근거가 없다는 뜻이고 앱에 넣지 않는다.
- `src/data/entries.json`에도 같은 항목을 기존 `id`와 같은 꼴로 더한다. 필드 설명은 [`DEVELOPMENT.md`](DEVELOPMENT.md)에 있다.
- 이름 언급 검사가 뒤 권 항목을 실제로 드러내지 않는 언급을 잡으면 매칭을 느슨하게 하지 말고, `src/lib/__tests__/data-guards.test.ts`의 `MENTION_EXCEPTIONS`에 사실과 이유를 적는다.

## GitHub 웹에서 고치기

로컬 설치 없이 고칠 수 있다.

1. GitHub에서 첫 번째 파일을 열고 연필 버튼을 누른다. 커밋하면 내 포크에 브랜치가 생긴다.
2. 두 번째 파일은 내 포크의 같은 브랜치에서 열어 고치고 그 브랜치에 커밋한다.
3. PR을 연다. 처음 기여하는 경우 포크 PR의 CI는 관리자가 실행을 승인한 뒤에 돈다.

## 빠른 시작

Node는 CI와 같은 22를 쓴다(`.nvmrc` 참고). pnpm 버전은 `package.json`에 정해져 있고 Corepack이 맞춰 준다.

```
corepack enable
pnpm install
pnpm start
```

데이터만 고쳤다면 `pnpm run test:ci`만 돌려도 된다.

## 코드 변경

패키지 매니저는 pnpm이다. PR 전에 아래가 모두 통과해야 한다. PR을 열면 CI가 같은 명령을 자동으로 돌린다. 데이터만 고쳐도 무결성 테스트와 아래 누수 검사가 돈다.

- 이름 언급: 사실 문장에 아직 그 권에 나오지 않은 항목의 이름이 있으면 실패한다.
- 종족 칩: 인물의 `race`가 인물보다 늦게 나오는 종족이면 실패한다.
- 초안 동기화: `docs/data-draft.md`와 `src/data/entries.json`의 문장, 권 번호, `[주요]`가 다르면 실패한다.

```
pnpm run typecheck && pnpm run test:ci && pnpm run lint
```

광고, 후원/결제, 분석 SDK는 추가하지 않는다.
